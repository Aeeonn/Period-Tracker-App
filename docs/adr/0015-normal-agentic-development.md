# ADR-0015: Normal agentic development

- **Status:** Accepted (owner decision, 2026-11-04). Supersedes [ADR-0009](0009-agent-operating-model-on-firstmate.md) and [ADR-0011](0011-vscode-copilot-orchestration.md). Amends [ADR-0012](0012-lighter-review-and-testing.md).
- **Context:** P0 and P1 were built with a Firstmate-style multi-agent workflow. An orchestrator wrote task briefs, dispatched builder, verifier, researcher, critic and planner agents into numbered worktree slots, tracked state in `docs/plan/backlog.md` and `~/firstmate`, and landed only exact reviewed SHAs. It worked, but the ceremony — briefs, slot management, status files, per-task routing and repeated reviews — cost more than it returned for a two-person app. The owner chose to move to ordinary agentic development.
- **Decision:**
  - One agent works directly with the owner. Each change goes on a short-lived feature branch in the primary checkout (or a worktree if the agent chooses), then fast-forwards into `main`. `main` is pushed to GitHub after every verified merge; only `main` is pushed.
  - [AGENTS.md](../../AGENTS.md) is the single entry point. Agents read it, then [docs/status.md](../status.md) for the current state and next steps and [docs/decisions.md](../decisions.md) for the owner's standing decisions. The approved plan, specs and ADRs stay authoritative for product behaviour.
  - Changes in sensitive areas (prediction or medical engine, crypto and keys, lock, pairing and sync, consent and sharing, migrations, backup/restore, delete-all, medical content, CSP and network policy) get, decided per change, an independent review by the `flo-reviewer` agent using the [`sensitive-change-review`](../../.agents/skills/sensitive-change-review/SKILL.md) skill. Other work relies on tests and self-review.
  - ADR-0012's policy remains: findings block only for correctness, security, data-loss or spec defects; nits become follow-ups; targeted tests plus `npm run check` per change; full E2E, the time-zone matrix, coverage, the backtest and benchmarks at phase end. Its Opus/Luna routing and per-wave batched reviews no longer apply.
  - Phase gates stay as owner check-ins: a short demo with a real-iPhone smoke check, then the owner decides whether to continue.
  - Removed: the six `flo-*` agents, the `flo-dispatch`, `flo-backlog`, `flo-worktree`, `flo-land`, `flo-commit` and `task-brief` skills, and `tools/agent-ops`. `verification-protocol` became `sensitive-change-review`. `docs/plan/backlog.md`, `task-briefs.md` and `agent-operating-model.md` are kept as frozen history and reference (task specs and dependencies), not as process.
- **Trade-off:** Less structure means less automatic independent checking and fewer written records per task. Mandatory tests, the `check` gate, per-change review for sensitive areas, phase-end full checks and the owner's phase gates keep the important safety nets. The owner can ask for a review on any change.
